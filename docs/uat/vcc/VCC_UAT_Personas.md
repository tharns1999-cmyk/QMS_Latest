# ตารางบทบาทผู้ใช้งานและเมทริกซ์สิทธิ์ระบบ VCC (VCC UAT Personas & Permission Matrix)

เอกสารฉบับนี้กำหนดบทบาทผู้ใช้งาน บัญชีทดสอบจำลอง (Test Accounts) และสิทธิ์การเข้าถึงข้อมูลตามตรรกะความปลอดภัยที่บังคับใช้จริงในระบบหลังบ้าน (`vccAuth.js`, `vccPlans.js`, `vccWorkOrders.js`) เพื่อใช้สำหรับกระบวนการทดสอบรับมอบระบบ (UAT) และการเตรียมความพร้อมสำหรับการตรวจประเมินคุณภาพ (Audit Readiness) ตามมาตรฐาน ISO 9001:2015 และ ISO/IEC 17025:2017

## 3. กฎเหล็กด้านการแบ่งแยกหน้าที่และความปลอดภัย (Separation of Duties & Security Rules)

### 3.1 การป้องกันการอนุมัติตนเอง (Strict Self-Approval Prevention)
ระบบมีกลไกป้องกันการลงนามอนุมัติตนเองในทุกขั้นตอนสำคัญอย่างเด็ดขาดที่ฝั่ง Backend API:
1. **การอนุมัติแผนประจำปี (Annual Plan Submission Gate)**:
   - ผู้จัดทำแผน (Preparer) **ห้าม** เลือกระบุตนเองเป็นผู้ทบทวน (`reviewer_id !== user.id`)
   - ผู้จัดทำแผน (Preparer) **ห้าม** เลือกระบุตนเองเป็นผู้อนุมัติ (`approver_id !== user.id`)
   - ผู้ทบทวนแผน (Reviewer) **ห้าม** เป็นบุคคลเดียวกับผู้อนุมัติ (`approver_id !== reviewer_id`)
   - หากตรวจพบ ระบบจะส่งข้อผิดพลาด HTTP 400 Bad Request พร้อมข้อความแจ้งเตือนที่ชัดเจน
2. **การตรวจรับปิดใบสั่งงาน (Work Order Review Gate)**:
   - ผู้บันทึกผลสอบเทียบ (Performer / `performed_by`) **ห้าม** ตรวจรับและอนุมัติปิดใบสั่งงานของตนเองเด็ดขาด (`user.id !== existing.performed_by`)
   - หากผู้บันทึกผลพยายามกดอนุมัติ ระบบจะส่งคืน HTTP 403 Forbidden: `"ผู้บันทึกผลไม่สามารถตรวจรับและอนุมัติปิดใบสั่งงานของตนเองได้"`

### 3.2 การจำกัดการเข้าถึงตามสังกัดแผนก (Department Isolation Policy)
- ผู้ใช้ระดับทั่วไป (L1–L5) จะมองเห็นและเข้าถึงข้อมูลเครื่องมือวัด แผนประจำปี และใบสั่งงาน **เฉพาะแผนกที่ตนเองสังกัดเท่านั้น** (เช่น `qc2` และ `qc4` จะมองไม่เห็นข้อมูลของ QA หรือ LB)
- ผู้ใช้ระดับบริหาร (L6 ขึ้นไป เช่น `qc6`), ผู้ดูแลเอกสาร (`dc4`), และตัวแทนฝ่ายบริหาร (`mg6`) มีสิทธิ์อ่านข้อมูลของทุกแผนกเพื่อการกำกับดูแล (Global Read Scope)
- **การแก้ไขและจัดการข้อมูล (Write Scope)**: แม้เป็นผู้ใช้ระดับ L6 ก็สามารถแก้ไขข้อมูลได้เฉพาะแผนกตนเองเท่านั้น ยกเว้น DCC (`dc4`) ที่มีสิทธิ์บริหารจัดการ Master Data และการโอนย้ายข้ามแผนก

### 3.3 การปลดระงับเครื่องมือวัด (Release Hold Policy)
เมื่อผลการสอบเทียบเป็น **FAIL** หรือไม่ผ่านเกณฑ์:
- ระบบจะปรับสถานะเครื่องมือวัดเป็น `ON_HOLD` โดยอัตโนมัติทันที
- ผู้ที่จะดำเนินการปลดระงับ (`POST /api/vcc/work-orders/:id/release-hold`) ต้องเป็นผู้มีอำนาจระดับ L5 ขึ้นไป (`qc6` หรือ `dc4`)
- **เงื่อนไขบังคับ**: ต้องกรอกข้อมูลครบถ้วนทั้ง 2 ส่วน:
  1. เหตุผลการปลดระงับและการแก้ไขที่ทำแล้ว (`release_reason`)
  2. ผลการประเมินผลกระทบต่อคุณภาพผลิตภัณฑ์ (NC Impact Assessment: `impact_assessment`)
- หากขาดข้อใดข้อหนึ่ง ระบบจะปฏิเสธการปลดระงับทันที (HTTP 400)
