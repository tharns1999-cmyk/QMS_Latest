# รายการตรวจสอบความพร้อมการทดสอบระบบ VCC (VCC UAT Execution Checklist)

เอกสารฉบับนี้ใช้สำหรับกำกับและตรวจสอบความพร้อมของสภาพแวดล้อม ข้อมูล และขั้นตอนก่อน ระหว่าง และหลังการทดสอบรับมอบระบบ (UAT) และการประเมิน Audit Readiness ของระบบ VCC

---

## ระยะที่ 1: การตรวจสอบความพร้อมก่อนเริ่มการทดสอบ (Pre-Execution Readiness)

| ลำดับ | รายการตรวจสอบ (Checklist Item) | วิธีการตรวจสอบ | เกณฑ์การยอมรับ (Acceptance Criteria) | ผู้ตรวจ | สถานะ |
| :---: | :--- | :--- | :--- | :---: | :---: |
| 1.1 | **สถานะฐานข้อมูลและ Migrations** | รัน `ls apps/api/migrations` และตรวจสอบโครงสร้าง D1 | ไฟล์ Migration ลำดับ 0001–0039 ถูกนำไปใช้อย่างสมบูรณ์ ไม่มี Migration ค้าง | Tech Lead | [ ] ผ่าน |
| 1.2 | **ข้อมูลทดสอบจำลอง (Seed Data)** | รันคำสั่ง `pnpm --dir apps/api run db:seed:local` | ข้อมูลผู้ใช้จำลอง (`dc4`, `qc2`, `qc4`, `qc6`, `mg6`, `qa4`) และเครื่องมือวัดติดป้าย `[ข้อมูลทดสอบ]` ครบถ้วน | QA Tester | [ ] ผ่าน |
| 1.3 | **ระบบจัดเก็บไฟล์จำลอง (R2 Storage)** | ตรวจสอบ Binding `FILES` ใน Worker Localhost | รองรับการอัปโหลดและดาวน์โหลดไฟล์จำลองในโหมดเครื่องเสมือน (Local Miniflare/Wrangler) | Backend Coder | [ ] ผ่าน |
| 1.4 | **กลไกพิทักษ์ประวัติ (Audit Log Guard)** | ตรวจสอบ SQLite Trigger ของตาราง `audit_log` | คำสั่ง `UPDATE` และ `DELETE` ต่อตาราง `audit_log` ถูกสกัดกั้นอย่างถาวร (Append-Only) | Security Auditor | [ ] ผ่าน |
| 1.5 | **การทำงานของ Web Frontend** | รัน `pnpm run dev` เปิดที่ `http://localhost:5173` | หน้าเว็บโหลดสมบูรณ์ ไม่มี Console Error และเข้าสู่ระบบได้ปกติ | Frontend Coder | [ ] ผ่าน |
| 1.6 | **การทำงานของ Worker API** | รัน `pnpm run dev:api` ที่ `http://127.0.0.1:8787` | API Healthcheck และ Route `/api/vcc/*` ตอบสนองถูกต้อง | Backend Coder | [ ] ผ่าน |
| 1.7 | **ไฟล์หลักฐานจำลอง (PDF Fixture)** | ตรวจสอบไฟล์ `sample_calibration_cert.pdf` ใน `fixtures/` | ไฟล์มีอยู่จริง ขนาด ~1 KB และสามารถเปิดแสดงผลได้ | QA Tester | [ ] ผ่าน |
| 1.8 | **การแยกระบบทดสอบออกจาก Production** | ตรวจสอบ URL, API Endpoint และ Data Binding | ยืนยันว่าการทดสอบทั้งหมดชี้ไปยัง `127.0.0.1` เท่านั้น ไม่เชื่อมต่อระบบจริง | Orchestrator | [ ] ผ่าน |

## ระยะที่ 2: การตรวจสอบระหว่างดำเนินการทดสอบ (During-Execution Checks)

| ลำดับ | รายการตรวจสอบ (Checklist Item) | วิธีการตรวจสอบ | เกณฑ์การยอมรับ (Acceptance Criteria) | ผู้ตรวจ | สถานะ |
| :---: | :--- | :--- | :--- | :---: | :---: |
| 2.1 | **การปฏิบัติตามกรณีทดสอบ** | รันตามขั้นตอนใน `VCC_UAT_Test_Cases.md` | ดำเนินการทดสอบครบทั้ง 8 Scenarios (VCC-UAT-001 ถึง VCC-UAT-008) | UAT Team | [ ] ผ่าน |
| 2.2 | **การทดสอบความปลอดภัยเชิงลบ (Negative Tests)** | ทดสอบการอนุมัติตนเอง และการเข้าถึงข้ามแผนก | ระบบต้องปฏิเสธ (400 หรือ 403) พร้อมข้อความแจ้งเตือนที่ชัดเจน | Security Auditor | [ ] ผ่าน |
| 2.3 | **การบันทึกภาพหลักฐาน (Evidence Capture)** | บันทึกภาพหน้าจอและเอกสาร PDF | บันทึกไฟล์ตามรูปแบบ `VCC-UAT-<ID>_<PERSONA>_<STEP>.png` ครบทุกขั้นตอนสำคัญ | UAT Team | [ ] ผ่าน |
| 2.4 | **การตรวจจับและบันทึก Defect** | บันทึกข้อบกพร่องลงใน `VCC_UAT_Defect_Log.md` | ระบุระดับความรุนแรง (Blocker, Critical, Major, Minor) และข้อมูลจำลองที่ใช้ | QA Tester | [ ] ผ่าน |
| 2.5 | **การทดสอบบนอุปกรณ์พกพา** | ทดสอบผ่านเบราว์เซอร์โหมดมือถือ (< 640px) | ปุ่มสัมผัส >= 44×44px, ฟอร์มไม่ล้นจอ, ป้องกัน Dirty Form ชัดเจน | Frontend Coder | [ ] ผ่าน |

## ระยะที่ 3: การตรวจสอบและสรุปผลหลังการทดสอบ (Post-Execution Verification)

| ลำดับ | รายการตรวจสอบ (Checklist Item) | วิธีการตรวจสอบ | เกณฑ์การยอมรับ (Acceptance Criteria) | ผู้ตรวจ | สถานะ |
| :---: | :--- | :--- | :--- | :---: | :---: |
| 3.1 | **ความสมบูรณ์ของ Audit Trail** | รันคำสั่ง SQL ตรวจสอบประวัติการบันทึก | มีการบันทึก Audit Log ของทุกกิจกรรมสำคัญ (`VCC_ASSET_*`, `VCC_PLAN_*`, `VCC_WO_*`) | Security Auditor | [ ] ผ่าน |
| 3.2 | **การประเมินข้อบกพร่อง (Defect Triage)** | ตรวจสอบรายการ Defect คงค้าง | ข้อบกพร่องระดับ **Blocker = 0** และ **Critical = 0** | Orchestrator | [ ] ผ่าน |
| 3.3 | **การตรวจรับรองเอกสาร Digital Record** | ตรวจสอบเอกสารผลการสอบเทียบดิจิทัล | แสดงผลครบถ้วน รองรับการพิมพ์ A4 หลายหน้าโดยไม่มีข้อมูลสูญหาย | Lead Auditor | [ ] ผ่าน |
| 3.4 | **การจัดทำรายงานสรุปและลงนาม** | กรอกข้อมูลใน `VCC_UAT_Summary_and_Signoff.md` | ผู้แทนฝ่าย DCC, QC/QA และ QMR ลงนามรับทราบผลการทดสอบ | UAT Lead | [ ] ผ่าน |
