# รายละเอียดกรณีทดสอบระบบ VCC (VCC UAT Executable Test Cases)

เอกสารชุดนี้ประกอบด้วยกรณีทดสอบภาคปฏิบัติ 8 กรณีหลัก (VCC-UAT-001 ถึง VCC-UAT-008) ที่ออกแบบมาเพื่อรองรับการทดสอบรับมอบระบบ (User Acceptance Testing: UAT) และการประเมินความพร้อมด้านการตรวจประเมินคุณภาพ (Audit Readiness) ตามมาตรฐาน ISO 9001:2015 (ข้อ 7.1.5, 7.5, 8.7) และ ISO/IEC 17025:2017 (ข้อ 6.4, 7.8)

---

## ดัชนีชุดการทดสอบ (Test Case Index)

1. [VCC-UAT-001: การขึ้นทะเบียนเครื่องมือวัดเดี่ยวและชุดรวม (Asset Registration & Composite Set Linking)](#vcc-uat-001)
2. [VCC-UAT-002: การจัดทำ ทบทวน และขออนุมัติแผนประจำปี (Annual Plan Workflow & Self-Approval Prevention)](#vcc-uat-002)
3. [VCC-UAT-003: การเปิดใบสั่งงานในแผนและนอกแผนเร่งด่วน (Work Order Creation: Planned & Ad-hoc)](#vcc-uat-003)
4. [VCC-UAT-004: บันทึกผลสอบเทียบ อัปโหลดใบรับรอง และตรวจสอบ SHA-256 (Calibration Result Recording & Integrity)](#vcc-uat-004)
5. [VCC-UAT-005: ตรวจรับผล ปิดงาน และกลไกระงับเครื่องมืออัตโนมัติ (Work Order Review: PASS vs FAIL / ON_HOLD)](#vcc-uat-005)
6. [VCC-UAT-006: การขอแก้ไขผลการสอบเทียบอย่างควบคุม (Controlled Amendment Trail)](#vcc-uat-006)
7. [VCC-UAT-007: การประเมินผลกระทบต่อคุณภาพและการปลดระงับเครื่องมือ (NC Impact Assessment & Release Hold)](#vcc-uat-007)
8. [VCC-UAT-008: การใช้งานผ่านอุปกรณ์พกพาและการพิมพ์เอกสารดิจิทัลหลายหน้า (Mobile Ergonomics & Multi-page Print)](#vcc-uat-008)

### VCC-UAT-001: การขึ้นทะเบียนเครื่องมือวัดเดี่ยวและชุดรวม (Asset Registration & Composite Set Linking)

- **รหัสกรณีทดสอบ:** `VCC-UAT-001`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 7.1.5.1), ISO/IEC 17025:2017 (ข้อ 6.4.4)
- **ผู้รับผิดชอบการทดสอบ:** เจ้าหน้าที่ควบคุมเอกสาร DCC (`dc4`) หรือหัวหน้าแผนก QC (`qc4`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - ระบบทำงานบนสภาพแวดล้อม Localhost พร้อมข้อมูล Seed เรียบร้อยแล้ว
  - ผู้ใช้งานเข้าสู่ระบบด้วยบัญชี `dc4` (รหัสผ่าน: `1234`)
- **ข้อมูลทดสอบ (Test Data):**
  - เครื่องมือเดี่ยว: รหัส `VM-001`, ชื่อ `[ข้อมูลทดสอบ] ดิจิทัลมัลติมิเตอร์ Fluke 87V`, แผนก `QC`, ช่วงการวัด `0 - 1000V`, ค่าความคลาดเคลื่อนที่ยอมรับได้ (MPE) `±0.05%`
  - เครื่องมือชุดรวม: รหัส `GB-SET-01`, ชื่อ `[ข้อมูลทดสอบ] ชุดเกจบล็อกมาตรฐาน (Gauge Block Set 83 ชิ้น)`, ลักษณะกลุ่ม `COMPOSITE_SET`
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วยบัญชี `dc4` เข้าสู่เมนู **VCC (ทะเบียนเครื่องมือวัด)**
  2. คลิกปุ่ม **"ลงทะเบียนเครื่องมือวัดใหม่"** กรอกข้อมูลเครื่องมือเดี่ยว `VM-001` ให้ครบถ้วนแล้วกดบันทึก
  3. ตรวจสอบว่าเครื่องมือปรากฏในรายการ และแสดงสถานะ `ACTIVE`
  4. คลิกปุ่ม **"ลงทะเบียนเครื่องมือวัดใหม่"** เพื่อสร้างชุดรวม `GB-SET-01` โดยเลือกประเภทกลุ่มเป็น **"ชุดรวม (Composite Set)"**
  5. บันทึกข้อมูล และตรวจสอบการแสดงผลป้าย `Composite Set` บนหน้าจอ
  6. ทดสอบความปลอดภัย (Negative Test): สลับบัญชีเป็น `qc2` แล้วตรวจสอบว่าปุ่ม "ลงทะเบียนเครื่องมือวัดใหม่" หรือสิทธิ์การสร้างเครื่องมือถูกจำกัดหรือไม่
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - เครื่องมือ `VM-001` และ `GB-SET-01` ถูกสร้างสำเร็จ แสดงข้อมูลครบถ้วน และมีบันทึกใน Audit Log (`VCC_ASSET_CREATED`)
  - เครื่องมือชุดรวมแสดงสัญลักษณ์หรือป้ายประเภทชัดเจน
  - ผู้ใช้ `qc2` ไม่สามารถสร้างเครื่องมือวัดใหม่ได้ (ไม่มีปุ่มหรือได้รับข้อความแจ้งเตือนปฏิเสธสิทธิ์)
- **ผลการทดสอบจริง (Actual Result):** *(รอกรอกผลการทดสอบ)*
- **สถานะ (Status):** `Pending`
- **หลักฐานอ้างอิง (Evidence Ref):** `VCC-UAT-001_DC4_AssetRegister.png`

### VCC-UAT-002: การจัดทำ ทบทวน และขออนุมัติแผนประจำปี (Annual Plan Workflow & Self-Approval Prevention)

- **รหัสกรณีทดสอบ:** `VCC-UAT-002`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 7.1.5.2), ISO/IEC 17025:2017 (ข้อ 6.4.6)
- **ผู้รับผิดชอบการทดสอบ:** ผู้จัดทำแผน (`qc4`), ผู้ทบทวน (`mg6`), ผู้อนุมัติ (`qc6`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - มีเครื่องมือวัดสถานะ `ACTIVE` ของแผนก `QC` อยู่ในระบบอย่างน้อย 2 รายการ
  - ผู้ใช้งานเข้าสู่ระบบด้วยบัญชี `qc4` (ระดับ L4)
- **ข้อมูลทดสอบ (Test Data):**
  - แผนประจำปี พ.ศ. 2569 (ค.ศ. 2026), แผนก `QC`
  - รายการเครื่องมือ: `ST002` กำหนดสอบเทียบเดือนมีนาคม และกันยายน
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วย `qc4` ไปที่แท็บ **"แผนการสอบเทียบประจำปี"** คลิกสร้างร่างแผนปี 2026
  2. เพิ่มเครื่องมือ `ST002` กำหนดรอบเดือนมีนาคม และกันยายน พร้อมระบุวัตถุประสงค์
  3. คลิกปุ่ม **"ส่งขออนุมัติแผน"** เพื่อเปิดหน้าต่างเลือกผู้มีอำนาจ
  4. **ทดสอบการป้องกันการอนุมัติตนเองฝั่งหน้าจอ (UI Self-Approval Prevention Check):**
     - ตรวจสอบรายการตัวเลือกในช่อง "ผู้ทบทวน (Reviewer)" ยืนยันว่า **ไม่มีชื่อ `qc4` (ตนเอง)** แสดงในรายการตัวเลือก
     - ตรวจสอบรายการตัวเลือกในช่อง "ผู้อนุมัติ (Approver)" ยืนยันว่า **ไม่มีชื่อ `qc4` (ตนเอง)** แสดงในรายการตัวเลือก
  5. **ทดสอบการป้องกันการอนุมัติตนเองและการทบทวนซ้ำฝั่ง API (API Self-Approval Prevention Check):**
     - ทดสอบส่งคำขอผ่าน API ด้วย `reviewer_id = 'qc4'` -> ตรวจสอบว่าระบบส่งคืน HTTP 400 `"ผู้จัดทำไม่สามารถเป็นผู้ทบทวนแผนของตนเองได้"`
     - ทดสอบส่งคำขอผ่าน API ด้วย `approver_id = 'qc4'` -> ตรวจสอบว่าระบบส่งคืน HTTP 400 `"ผู้จัดทำไม่สามารถเป็นผู้อนุมัติแผนของตนเองได้"`
     - ทดสอบส่งคำขอผ่าน API ด้วย `reviewer_id = 'qc6'` และ `approver_id = 'qc6'` -> ตรวจสอบว่าระบบส่งคืน HTTP 400 `"ผู้ทบทวนไม่สามารถเป็นผู้อนุมัติแผนที่ตนทบทวนได้"`
  6. **การดำเนินการตามขั้นตอนปกติ (Happy Path Flow):**
     - บนหน้าต่างส่งขออนุมัติ: เลือกระบุผู้ทบทวนเป็น `mg6` (MGT ผู้จัดการ / QMR L6)
     - สังเกตว่าในช่องผู้อนุมัติ ตัวเลือก `mg6` จะถูกตัดออกโดยอัตโนมัติตามหลัก 4-Eyes Principle
     - เลือกระบุผู้อนุมัติเป็น `qc6` (QC ผู้จัดการ L6) แล้วกดยืนยันส่งแผน
  7. สลับบัญชีเข้าสู่ระบบด้วย `mg6` เปิดดูแผนประจำปี 2026 ตรวจสอบรายละเอียดและกด **"ผ่านการทบทวน (Review)"**
  8. สลับบัญชีเข้าสู่ระบบด้วย `qc6` เปิดดูแผนประจำปี 2026 ตรวจสอบความสมบูรณ์และกด **"อนุมัติแผน (Approve)"**
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - ในขั้นตอนที่ 4: หน้าจอไม่แสดงชื่อผู้จัดทำในรายการเลือกผู้ทบทวน/ผู้อนุมัติ
  - ในขั้นตอนที่ 5: API ปฏิเสธการอนุมัติตนเองและการควบสองตำแหน่งทุกกรณี (HTTP 400)
  - ในขั้นตอนที่ 6–8: แผนถูกส่ง ทบทวนโดย `mg6` และอนุมัติโดย `qc6` สำเร็จ สถานะเปลี่ยนเป็น `APPROVED` พร้อมบันทึก Audit Log ครบถ้วน
- **ผลการทดสอบจริง (Actual Result):** *(รอกรอกผลการทดสอบในการดำเนินการ Phase 2)*
- **สถานะ (Status):** `Pending`
- **หลักฐานอ้างอิง (Evidence Ref):** `VCC-UAT-002_Plan_SelfApproval_Blocked.png`, `VCC-UAT-002_Plan_Approved.png`

### VCC-UAT-003: การเปิดใบสั่งงานในแผนและนอกแผนเร่งด่วน (Work Order Creation: Planned & Ad-hoc)

- **รหัสกรณีทดสอบ:** `VCC-UAT-003`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 7.1.5.2), ISO/IEC 17025:2017 (ข้อ 6.4.7)
- **ผู้รับผิดชอบการทดสอบ:** เจ้าหน้าที่ QC (`qc2`) หรือหัวหน้างาน (`qc4`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - มีแผนประจำปี 2026 ที่สถานะ `APPROVED` อยู่ในระบบ
- **ข้อมูลทดสอบ (Test Data):**
  - ใบสั่งงานในแผน: อ้างอิงรอบเดือนมีนาคมของเครื่องมือ `ST002`
  - ใบสั่งงานนอกแผน (Ad-hoc): เครื่องมือ `TC001`, ประเภทงาน `ทวนสอบเร่งด่วนหลังการซ่อมบำรุง`, วันครบกำหนด: วันที่ปัจจุบัน + 3 วัน
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วย `qc2` เข้าสู่เมนู **"ใบสั่งงาน (Work Orders)"**
  2. เปิดใบสั่งงานจากแผนประจำปีที่อนุมัติแล้ว ตรวจสอบว่าระบบเติมข้อมูลเครื่องมือและวันที่กำหนดให้อัตโนมัติ
  3. คลิกปุ่ม **"เปิดใบสั่งงานใหม่"** เลือกประเภท **"นอกแผน (Ad-hoc)"**
  4. เลือกเครื่องมือ `TC001` ระบุเหตุผลการเปิดงานนอกแผน และกำหนดวันครบกำหนด
  5. บันทึกใบสั่งงาน และตรวจสอบรหัสใบสั่งงาน (WO Code) ที่สร้างขึ้น
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - ใบสั่งงานทั้ง 2 ฉบับถูกสร้างขึ้นในสถานะ `OPEN`
  - มีรหัสเอกสารเฉพาะ (เช่น `WO-QC-2026-XXXX`) และระบุประเภทงานอย่างถูกต้องชัดเจน
  - ข้อมูลบันทึกประวัติ Audit Log ถูกสร้างขึ้นอย่างถูกต้อง
- **ผลการทดสอบจริง (Actual Result):** *(รอกรอกผลการทดสอบ)*
- **สถานะ (Status):** `Pending`

### VCC-UAT-004: บันทึกผลสอบเทียบ อัปโหลดใบรับรอง และตรวจสอบ SHA-256 (Calibration Result Recording & Integrity)

- **รหัสกรณีทดสอบ:** `VCC-UAT-004`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 7.1.5.2), ISO/IEC 17025:2017 (ข้อ 7.8.2)
- **ผู้รับผิดชอบการทดสอบ:** เจ้าหน้าที่ผู้ปฏิบัติงานสอบเทียบ (`qc2`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - มีใบสั่งงานสถานะ `OPEN` ของเครื่องมือ `ST002`
  - เตรียมไฟล์ใบรับรองตัวอย่าง `sample_calibration_cert.pdf` (ขนาด < 10 MB)
- **ข้อมูลทดสอบ (Test Data):**
  - ผลการสอบเทียบ: `PASS`
  - เลขที่ใบรับรอง (Certificate No.): `CERT-2026-QC-001`
  - สถาบัน/ห้องปฏิบัติการที่สอบเทียบ: `สถาบันมาตรวิทยาแห่งชาติ (มว.)`
  - ค่าความผิดพลาดสูงสุดที่พบ (Max Error): `0.02 °C` (เกณฑ์ยอมรับ: `±0.10 °C`)
  - ค่าความไม่แน่นอนในการวัด (Expanded Uncertainty $U$): `0.01 °C` ($k=2$)
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วย `qc2` เปิดใบสั่งงานของ `ST002`
  2. คลิกปุ่ม **"บันทึกผลการสอบเทียบ"**
  3. กรอกข้อมูลผลการสอบเทียบ วันที่สอบเทียบ เลขที่ใบรับรอง สถาบัน และค่าทางมาตรวิทยา
  4. ลากวางไฟล์ `sample_calibration_cert.pdf` เข้าสู่ช่องแนบเอกสาร
  5. ตรวจสอบการพรีวิวไฟล์ และกด **"บันทึกและส่งตรวจรับผล"**
  6. ตรวจสอบสถานะใบสั่งงานที่เปลี่ยนเป็น `PENDING_REVIEW`
  7. ตรวจสอบว่าระบบคำนวณและแสดงค่ารหัสตรวจสอบความถูกต้องไฟล์ (SHA-256 Checksum Hash) บนหน้าจอตรงกับ `f3b6026cad6f1ddc7d6d096454623a422a8044d268e1a4d5a2dce397f19c1c38`
  8. คลิกปุ่ม **"ดาวน์โหลดใบรับรอง"** เพื่อบันทึกไฟล์กลับลงมาในเครื่อง และคำนวณค่า SHA-256 ของไฟล์ที่ดาวน์โหลดมา เพื่อตรวจยืนยันความสมบูรณ์ของไฟล์จริง
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - บันทึกผลสำเร็จ สถานะเปลี่ยนเป็น `PENDING_REVIEW`
  - ไฟล์แนบถูกจัดเก็บในระบบและสามารถเปิดดาวน์โหลดตรวจสอบได้
  - ค่า Checksum SHA-256 ที่ระบบคำนวณและค่าของไฟล์ที่ดาวน์โหลดกลับมาตรงกัน (`f3b6...`) ยืนยันความสมบูรณ์ของหลักฐานดิจิทัลตาม ISO/IEC 17025 ข้อ 7.8.2
  - ไม่สามารถแก้ไขข้อมูลผลการสอบเทียบได้โดยตรงในสถานะนี้

### VCC-UAT-005: ตรวจรับผล ปิดงาน และกลไกระงับเครื่องมืออัตโนมัติ (Work Order Review: PASS vs FAIL / ON_HOLD)

- **รหัสกรณีทดสอบ:** `VCC-UAT-005`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 7.1.5.1, 7.1.5.2), ISO/IEC 17025:2017 (ข้อ 6.4.7, 7.8.6)
- **ผู้รับผิดชอบการทดสอบ:** ผู้ตรวจรับผล L5+ (`qc6`), ผู้บันทึกผล (`qc2`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - มีใบสั่งงานที่ 1 ผล `PASS` บันทึกโดย `qc2`
  - มีใบสั่งงานที่ 2 ผล `FAIL` (ค่า Error เกินเกณฑ์ MPE) บันทึกโดย `qc2`
- **ข้อมูลทดสอบ (Test Data):**
  - ใบสั่งงานที่ 1: ผล PASS -> คาดหวังเครื่องมือยังคงสถานะ `ACTIVE`
  - ใบสั่งงานที่ 2: ผล FAIL -> คาดหวังเครื่องมือถูกปรับสถานะเป็น `ON_HOLD`
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วย `qc2` (ผู้บันทึกผล) ลองกดปุ่ม **"อนุมัติปิดงาน"** ในใบสั่งงานที่ 1 (Negative Test: ป้องกันการอนุมัติตนเอง)
  2. ตรวจสอบการปฏิเสธของระบบ
  3. สลับบัญชีเข้าสู่ระบบด้วย `qc6` (ผู้จัดการฝ่าย QC ระดับ L6)
  4. เปิดใบสั่งงานที่ 1 (PASS) ตรวจสอบความถูกต้องของใบรับรอง แล้วกด **"อนุมัติและปิดใบสั่งงาน"**
  5. ตรวจสอบสถานะใบสั่งงานที่ 1 (เปลี่ยนเป็น `CLOSED`) และสถานะเครื่องมือ `ST002` (คงสถานะ `ACTIVE`)
  6. เปิดใบสั่งงานที่ 2 (FAIL) และกดอนุมัติตรวจรับผล
  7. ตรวจสอบสถานะใบสั่งงานที่ 2 (เปลี่ยนเป็น `CLOSED` และแสดงป้าย `NC OPEN`)
  8. ไปที่หน้าทะเบียนเครื่องมือวัด ตรวจสอบสถานะของเครื่องมือในใบสั่งงานที่ 2
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - ขั้นตอนที่ 1: ระบบต้องแจ้งเตือนข้อผิดพลาด: `"ผู้บันทึกผลไม่สามารถตรวจรับและอนุมัติปิดใบสั่งงานของตนเองได้"`
  - ขั้นตอนที่ 5: ใบสั่งงานที่ 1 ปิดงานสำเร็จ เครื่องมือยังคงใช้งานได้ตามปกติ (`ACTIVE`)
  - ขั้นตอนที่ 7–8: เครื่องมือในใบสั่งงานที่ 2 ถูกระบบปรับเปลี่ยนสถานะเป็น **`ON_HOLD`** โดยอัตโนมัติ พร้อมแสดงป้ายเตือนระงับการใช้งานทันที

- **รหัสกรณีทดสอบ:** `VCC-UAT-006`

### VCC-UAT-007: การประเมินผลกระทบต่อคุณภาพและการปลดระงับเครื่องมือ (NC Impact Assessment & Release Hold)

- **รหัสกรณีทดสอบ:** `VCC-UAT-007`
- **การเชื่อมโยงมาตรฐาน:** ISO 9001:2015 (ข้อ 8.7 การควบคุมผลลัพธ์ที่ไม่เป็นไปตามข้อกำหนด), ISO/IEC 17025:2017 (ข้อ 6.4.7)
- **ผู้รับผิดชอบการทดสอบ:** ผู้จัดการฝ่าย QC L6 (`qc6`) หรือ DCC Admin (`dc4`)
- **เงื่อนไขเบื้องต้น (Preconditions):**
  - มีเครื่องมือวัดที่อยู่ในสถานะ `ON_HOLD` จากผลการสอบเทียบไม่ผ่านเกณฑ์ใน VCC-UAT-005
- **ข้อมูลทดสอบ (Test Data):**
  - การแก้ไข: `ส่งซ่อมและปรับเทียบใหม่โดยผู้ผลิต ผ่านการสอบเทียบซ้ำเรียบร้อยแล้ว`
  - การประเมินผลกระทบ (NC Impact Assessment): `จากการตรวจสอบย้อนกลับผลิตภัณฑ์ที่ผลิตด้วยเครื่องมือนี้ในรอบ 14 วันที่ผ่านมา ค่าความคลาดเคลื่อนไม่ส่งผลต่อข้อกำหนดวิกฤตของผลิตภัณฑ์ (No Risk to Product Safety/Quality)`
- **ขั้นตอนการทดสอบ (Test Steps):**
  1. เข้าสู่ระบบด้วย `qc4` (ระดับ L4) ลองกดปุ่ม **"ปลดระงับเครื่องมือ (Release Hold)"** (Negative Test 1: สิทธิ์ไม่ถึง L5)
  2. ตรวจสอบการปฏิเสธของระบบ
  3. เข้าสู่ระบบด้วย `qc6` (ระดับ L6) เปิดใบสั่งงานที่ติดระงับ
  4. คลิกปุ่ม **"ปลดระงับเครื่องมือ (Release Hold)"**
  5. ทดสอบไม่กรอกช่อง "การประเมินผลกระทบ" แล้วกดยืนยัน (Negative Test 2: บังคับกรอก Impact Assessment)
  6. ตรวจสอบข้อความแจ้งเตือนข้อผิดพลาด
  7. กรอกข้อมูลครบถ้วนทั้งเหตุผลการแก้ไขและการประเมินผลกระทบต่อผลิตภัณฑ์ แล้วกดยืนยัน
  8. ตรวจสอบสถานะของเครื่องมือวัดในหน้าทะเบียน
- **ผลลัพธ์ที่คาดหวัง (Expected Results):**
  - ขั้นตอนที่ 1: ผู้ใช้ L4 ไม่สามารถปลดระงับได้ ระบบต้องแจ้งเตือนสิทธิ์ไม่เพียงพอ
  - ขั้นตอนที่ 5: ระบบปฏิเสธพร้อมแจ้งเตือน: `"กรุณาระบุผลการประเมินผลกระทบและการแก้ไข (NC Impact Assessment) ก่อนปลดระงับเครื่องมือ"`
  - ขั้นตอนที่ 7–8: ปลดระงับสำเร็จ สถานะเครื่องมือเปลี่ยนกลับเป็น `ACTIVE`, สถานะ NC เปลี่ยนเป็น `RESOLVED` และมีบันทึกใน Audit Log ครบถ้วน
