# เอกสารสรุปผลการทดสอบรับมอบระบบและใบลงนามอนุมัติ (VCC UAT Summary & Sign-off Document)

เอกสารฉบับนี้ใช้สำหรับกำหนดเกณฑ์การประเมินผลการทดสอบรับมอบระบบ (User Acceptance Testing: UAT) การวิเคราะห์ช่องว่าง (Gap Analysis) การประเมินความเสี่ยง และแบบฟอร์มการลงนามอนุมัติความพร้อมของระบบควบคุมการสอบเทียบและทวนสอบเครื่องมือวัด (Verify and Calibration Center: VCC) ก่อนการพิจารณาส่งมอบเพื่อเตรียมขึ้นใช้งานจริง

> **สถานะปัจจุบัน**: **PENDING / NOT RUN (เตรียมความพร้อมเอกสารและกรณีทดสอบ Phase 1 เรียบร้อย อยู่ระหว่างเตรียมการทดสอบจริงใน Phase 2)**  
> **หลักการสำคัญ**: ยังไม่มีการลงมติรับมอบระบบ (Go/No-Go) จนกว่ากระบวนการทดสอบภาคปฏิบัติใน Phase 2 จะเสร็จสิ้นและมีหลักฐานการทดสอบ (Execution Evidence) ครบถ้วนทุกกรณี

---

## 1. บทสรุปสำหรับผู้บริหาร (Executive Summary)

ระบบ VCC ได้รับการพัฒนาและกำหนดเกณฑ์การทดสอบให้ครอบคลุมกระบวนการควบคุมเครื่องมือวัดตามข้อกำหนดมาตรฐานสากล:
- **ISO 9001:2015** ข้อ 7.1.5 (ทรัพยากรในการเฝ้าติดตามและการวัด), ข้อ 7.5 (ข้อมูลเอกสาร), และข้อ 8.7 (การควบคุมผลลัพธ์ที่ไม่เป็นไปตามข้อกำหนด)
- **ISO/IEC 17025:2017** ข้อ 6.4 (เครื่องมือวัดและอุปกรณ์), ข้อ 7.8 (การรายงานผลการสอบเทียบ), และข้อ 7.8.8 (การแก้ไขรายงานผล)

การทดสอบในระยะ Phase 1 (Test Preparation & Readiness) ได้จัดเตรียมกรณีทดสอบ ข้อมูลจำลอง และสภาพแวดล้อมในเครื่องเสมือน (Isolated Localhost Testing Environment) โดยไม่มีการแตะต้องฐานข้อมูลจริงหรือระบบ Production ตามกฎ Brownfield Rules

## 3. การวิเคราะห์ช่องว่างและการประเมินความเสี่ยง (Gap Analysis & Operational Risks)

เพื่อให้เกิดความเข้าใจที่ถูกต้องตรงกันระหว่างทีมพัฒนาระบบ ผู้ใช้งาน และผู้ตรวจประเมินคุณภาพ ขอระบุขอบเขตและข้อพิจารณาสำคัญดังนี้:

1. **ขอบเขตการอ้างอิงมาตรฐาน (Accreditation vs System Compliance):**
   - ระบบ VCC ถูกออกแบบและพัฒนา **"ตามแนวทางข้อกำหนดมาตรฐาน ISO 9001:2015 และ ISO/IEC 17025:2017"** ในการจัดเก็บข้อมูล ควบคุมความคลาดเคลื่อน และบันทึกประวัติที่แก้ไขไม่ได้
   - ตัวระบบซอฟต์แวร์เพียงลำพังมิได้ถือเป็นการได้รับการรับรองระบบงานห้องปฏิบัติการ (Accreditation) โดยอัตโนมัติ สถาบันหรือห้องปฏิบัติการภายนอกที่ส่งเครื่องมือไปสอบเทียบยังคงต้องได้รับการรับรองตาม ISO/IEC 17025 จริง และเอกสารใบรับรองต้องจัดเก็บเป็นหลักฐานอ้างอิงในระบบ
2. **การปฏิบัติการหน้างานควบคู่กับระบบดิจิทัล (Dual-Control at Physical Shopfloor):**
   - เมื่อระบบปรับสถานะเครื่องมือเป็น `ON_HOLD` ผู้ดูแลเครื่องมือต้องทำการติดป้ายหรือคล้องป้ายเตือนทางกายภาพ (Physical Tagging) ที่ตัวเครื่องมือวัดจริงทันที เพื่อป้องกันพนักงานหน้างานหยิบไปใช้งานโดยไม่สังเกตในระบบ
3. **การยืนยันตัวตนสองชั้น (Two-Factor Authentication: 2FA):**
   - ในสภาพแวดล้อมทดสอบ Localhost ค่า 2FA ถูกปิดไว้เพื่อความสะดวกในการสลับบัญชีทดสอบ
   - ก่อนการขึ้นระบบใช้งานจริง (Production Deployment) แนะนำให้เปิดใช้งานระบบ 2FA ในเมนู Master Data > Security สำหรับผู้ใช้ระดับ L5 ขึ้นไปและเจ้าหน้าที่ DCC เพื่อเพิ่มระดับความปลอดภัยสูงสุดตามนโยบายองค์กร
4. **ความแตกต่างของขอบเขตสิทธิ์ข้ามแผนก (Cross-Department Scope Analysis):**
   - ในระดับ API: ผู้ใช้ระดับ L6, QMR (`mg6`) และ DCC (`dc4`) มีสิทธิ์อ่านข้อมูลของทุกแผนก (Global Read Scope) เพื่อการกำกับดูแล
   - ในการจัดการแผนประจำปีและใบสั่งงาน: ผู้ใช้ระดับ L6 และ QMR สามารถทบทวนหรืออนุมัติข้ามแผนกได้ตามฟังก์ชัน `isUserAuthorizedForPlanDept`
   - แต่ในการจัดการทะเบียนเครื่องมือวัด (Asset Register): การแก้ไขข้อมูลจำกัดเฉพาะ DCC และเจ้าหน้าที่แผนกตนเองระดับ L4 ขึ้นไปเท่านั้น ผู้ใช้ L6 ที่สังกัดแผนกอื่นไม่สามารถแก้ไขทะเบียนเครื่องมือของแผนกอื่นได้ ซึ่งเป็นการจำกัดขอบเขตการแก้ไขอย่างรัดกุม
