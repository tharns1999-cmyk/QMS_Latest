# นโยบายและแหล่งจัดเก็บหลักฐานการทดสอบรับมอบระบบ (VCC UAT Evidence Policy & Repository)

ไดเรกทอรีนี้ใช้สำหรับจัดเก็บหลักฐานดิจิทัลที่ได้จากการรันการทดสอบรับมอบระบบ (UAT) ใน Phase 2 ตามมาตรฐาน ISO 9001:2015 (ข้อ 7.5 ข้อมูลเอกสาร) และ ISO/IEC 17025:2017 (ข้อ 7.8 และข้อ 8.4 การควบคุมบันทึก)

---

## 1. นโยบายการควบคุมและจัดเก็บหลักฐาน (Evidence Storage Policy)

1. **การควบคุมการเข้าถึง (Access Control):**
   - ในระหว่างการทดสอบ UAT หลักฐานทั้งหมดจะถูกจัดเก็บในเครื่อง Localhost ของผู้ทดสอบ
   - ไฟล์หลักฐานจริง (ภาพหน้าจอ, ไฟล์ดาวน์โหลด, Log Export) จะถูกกันไม่ให้บันทึกขึ้น Git Repository ผ่าน `.gitignore` เพื่อป้องกันการรั่วไหลของข้อมูลการทดสอบและข้อมูลส่วนบุคคล (Zero PII in Git)
   - หลังเสร็จสิ้นการทดสอบ ชุดหลักฐานฉบับสมบูรณ์จะถูกจัดเก็บเป็นแพ็กเกจถาวรในระบบจัดเก็บเอกสารคุณภาพขององค์กร (QMS Electronic Archive) โดยจำกัดสิทธิ์เฉพาะผู้มีอำนาจของฝ่าย DCC, QC/QA และผู้ตรวจประเมินเท่านั้น
2. **ระยะเวลาการจัดเก็บ (Retention Period):**
   - หลักฐานการทดสอบรับมอบระบบและบันทึกผลการสอบเทียบต้องได้รับการจัดเก็บรักษาไว้เป็นเวลาไม่น้อยกว่า **10 ปี** ตามระเบียบปฏิบัติงานการควบคุมบันทึกคุณภาพขององค์กร
3. **การรักษาความสมบูรณ์ของไฟล์ (Integrity via SHA-256):**
   - ไฟล์ใบรับรองผลการสอบเทียบทุกไฟล์ที่อัปโหลดและดาวน์โหลด ต้องได้รับการตรวจสอบค่า SHA-256 Checksum Hash เสมอ เพื่อเป็นหลักฐานว่าไฟล์ไม่ถูกดัดแปลงแก้ไขภายหลัง
4. **การประทับเวลาสากล (Timestamping Standard):**
   - ทุกบันทึกและภาพถ่ายต้องระบุเวลาในรูปแบบ ISO 8601 UTC ในระดับระบบ และแสดงเวลาท้องถิ่นประเทศไทย (Bangkok GMT+7, พ.ศ.) บนหน้าจอ
5. **การสอบกลับได้ (Traceability):**
   - ทุกหลักฐานต้องสามารถเชื่อมโยงกลับไปยัง:
     - รหัสกรณีทดสอบ (Test Case ID: `VCC-UAT-XXX`)
     - บัญชีผู้ปฏิบัติงาน (Persona ID: `qc2`, `qc4`, `qc6`, `dc4`, `mg6`)
     - รหัสใบสั่งงาน (Work Order Code: `WO-QC-2026-XXXX`)
     - รหัสเครื่องมือวัด (Asset Code: `ST002`, `TC001`, `VM-001`, `GB-SET-01`)

## 2. โครงสร้างการจัดเก็บ (Directory Structure)

1. **`screenshots/`**:
   - ภาพถ่ายหน้าจอขณะดำเนินการทดสอบและผลลัพธ์
   - รูปแบบการตั้งชื่อไฟล์: `VCC-UAT-<ID>_<PERSONA>_<YYYYMMDD>_<STEP>.png`
   - ตัวอย่าง:
     - `VCC-UAT-001_DC4_20261105_AssetRegister.png`
     - `VCC-UAT-002_QC4_20261105_SelfApproval_Blocked.png`
     - `VCC-UAT-002_QC6_20261105_Plan_Approved.png`
     - `VCC-UAT-003_QC2_20261105_Planned_Adhoc_Created.png`
     - `VCC-UAT-004_QC2_20261105_Upload_Cert_Hash.png`
     - `VCC-UAT-005_QC2_20261105_Record_Fail_TC001.png`
     - `VCC-UAT-005_QC2_20261105_SelfApprove_Blocked.png`
     - `VCC-UAT-005_QC6_20261105_Auto_OnHold_TC001.png`
     - `VCC-UAT-006_QC6_20261105_Amended_Snapshot.png`
     - `VCC-UAT-007_QC6_20261105_Release_Hold_Assessment.png`
     - `VCC-UAT-008_QC2_20261105_Mobile_MultiPage_Print.png`

2. **`downloads/`**:
   - ไฟล์ใบรับรองหรือเอกสาร PDF ที่ผู้ทดสอบดาวน์โหลดกลับมาจากระบบ เพื่อตรวจความสมบูรณ์ของค่า SHA-256 Hash
   - ตัวอย่าง: `VCC-UAT-004_downloaded_cert_ST002.pdf`

3. **`audit_logs/`**:
   - ไฟล์ Export ข้อมูลประวัติการบันทึก Audit Trail จาก SQLite D1 ยืนยันว่ามี Event `VCC_ASSET_*`, `VCC_PLAN_*`, `VCC_WO_*` ครบถ้วน
   - ตัวอย่าง: `VCC-UAT-Phase2_audit_trail_export.json`
