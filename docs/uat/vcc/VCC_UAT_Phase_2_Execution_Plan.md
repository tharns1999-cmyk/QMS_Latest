# แผนการเตรียมการและแนวทางปฏิบัติการทดสอบระบบจริง (VCC UAT Phase 2 — Execution Preparation Plan)

เอกสารฉบับนี้กำหนดกรอบการปฏิบัติการ ลำดับการทดสอบ (Execution Sequence), บทบาทหน้าที่และการมอบหมายผู้ทดสอบจริง, การบริหารจัดการหลักฐาน (Evidence Management), กระบวนการคัดกรองข้อบกพร่อง (Defect Triage), และรายการตรวจสอบความปลอดภัยของสภาพแวดล้อมก่อนการเริ่มทดสอบรับมอบระบบ (UAT Preflight Checklist) ในระยะ Phase 2 ตามมาตรฐาน ISO 9001:2015 และ ISO/IEC 17025:2017

> **สถานะปัจจุบัน**: **PENDING PREFLIGHT & EXECUTION (เอกสารและสภาพแวดล้อมเตรียมพร้อมแล้ว — ยังไม่มีการรันผลการทดสอบจริง)**  
> **ข้อกำหนดความปลอดภัยสูงสุด**: ห้ามส่งขึ้นระบบจริง (Production) และห้ามแตะต้องฐานข้อมูลจริงเด็ดขาด การทดสอบดำเนินการบนสภาพแวดล้อม Localhost แบบแยกส่วนเท่านั้น

### 1.1 รายละเอียดขั้นตอน UAT-005 (Detailed Sequence for Work Order Review & Auto-Status)
เพื่อให้การทดสอบกลไกควบคุมสถานะเครื่องมือวัด (Auto-Status Control) สอดคล้องตามข้อกำหนด ISO 9001:2015 ข้อ 7.1.5.1 และ ISO/IEC 17025:2017 ข้อ 6.4.7 ลำดับขั้นตอนใน UAT-005 กำหนดไว้ดังนี้:
1. **การบันทึกผลไม่ผ่านเกณฑ์ (FAIL Recording by Performer):**  
   - ผู้ปฏิบัติงาน `qc2` เปิดใบสั่งงานนอกแผนของเครื่องมือ `TC001` (จาก UAT-003)
   - บันทึกผลการสอบเทียบเป็น `FAIL` โดยระบุค่า Max Error = `+1.85 °C` (เกณฑ์ยอมรับ MPE = `±0.50 °C`)
   - กดบันทึกและส่งตรวจรับผล สถานะใบสั่งงานเปลี่ยนเป็น `PENDING_REVIEW`
   - *หลักฐาน:* `VCC-UAT-005_QC2_20261105_Record_Fail_TC001.png`
2. **การทดสอบความปลอดภัย: ป้องกันการตรวจรับตนเอง (Self-Review Prevention Gate):**  
   - ผู้ปฏิบัติงาน `qc2` (ซึ่งเป็นผู้บันทึกผล) พยายามคลิกปุ่ม "อนุมัติปิดงาน" บนใบสั่งงานทั้งสองฉบับ
   - ระบบหน้าจอและ API ต้องปฏิเสธการดำเนินการด้วยรหัส HTTP 403: `"ผู้บันทึกผลไม่สามารถตรวจรับและอนุมัติปิดใบสั่งงานของตนเองได้"`
   - *หลักฐาน:* `VCC-UAT-005_QC2_20261105_SelfApprove_Blocked.png`
3. **การตรวจรับและปิดใบสั่งงานโดยผู้มีอำนาจ (Review by Approver):**  
   - สลับบัญชีเข้าสู่ระบบด้วยผู้จัดการฝ่าย QC `qc6` (ระดับ L6)
   - ตรวจรับใบสั่งงานฉบับที่ 1 (PASS, `ST002`) -> ปิดงานสำเร็จ สถานะเครื่องมือ `ST002` คงเป็น `ACTIVE`
   - ตรวจรับใบสั่งงานฉบับที่ 2 (FAIL, `TC001`) -> ปิดงานสำเร็จ (`CLOSED`, `NC OPEN`)
   - ระบบหลังบ้านปรับเปลี่ยนสถานะของเครื่องมือ `TC001` เป็น **`ON_HOLD`** โดยอัตโนมัติทันที
   - *หลักฐาน:* `VCC-UAT-005_QC6_20261105_Auto_OnHold_TC001.png`

## 3. มติการกำกับดูแลสิทธิ์และการทดสอบความปลอดภัยเชิงลบ (Governance & Negative Security Gates)

### 3.1 มติการกำกับดูแลสิทธิ์ข้ามแผนก (Governance Decision on Cross-Department Scope)
- **ผู้บริหารระดับสูง (L6+) และ QMR (`mg6`):** มีสิทธิ์มองเห็นข้อมูลทุกแผนก (Global Read Scope) และมีสิทธิ์ในระดับ API ในการทบทวน/อนุมัติแผนประจำปีและใบสั่งงานตามฟังก์ชัน `isUserAuthorizedForPlanDept` เพื่อรองรับการกำกับดูแลระดับบริหารและการลงนามแทน
- **นโยบายการปฏิบัติงานจริง (SOP Enforcement):** ในการรัน UAT ต้องจำกัดให้ผู้จัดการฝ่าย QC (`qc6`) เป็นผู้อนุมัติหลักของแผนก QC เพื่อรักษาการแบ่งแยกความรับผิดชอบตามสายงาน เว้นแต่มีคำสั่งมอบหมายอย่างเป็นทางการ
- **การจัดการทะเบียนเครื่องมือวัด (Asset Register):** ถูกแยกสิทธิ์อย่างเคร่งครัด โดยผู้ใช้ที่ไม่ใช่ DCC (รวมถึง L6 ของแผนกอื่น) ไม่สามารถสร้างหรือแก้ไขเครื่องมือของแผนกอื่นได้

## 5. รายการตรวจสอบความปลอดภัยของสภาพแวดล้อม (Environment Safety & Preflight Checklist)

> **คำเตือน**: คำสั่ง `db:seed:local` ทำหน้าที่เพียงเพิ่มข้อมูลผู้ใช้และข้อมูลจำลอง (`INSERT OR IGNORE`) เท่านั้น **ไม่ใช่คำสั่ง Reset หรือ Restore ฐานข้อมูลทั้งหมด** หากต้องการเริ่มต้นสภาพแวดล้อมใหม่ที่สะอาดสมบูรณ์ ให้ปฏิบัติตามขั้นตอนด้านล่างนี้

### 5.1 ขั้นตอนการเตรียมสภาพแวดล้อมใหม่แบบปลอดภัย (Safe Fresh Setup & Verification)
1. **การล้างฐานข้อมูลชั่วคราวและเริ่มระบบใหม่ (Clean Reset):**
   ```powershell
   # 1. หยุดการทำงานของ dev server ทั้งหมด
   # 2. ลบพื้นที่เก็บฐานข้อมูลจำลอง Miniflare
   Remove-Item -Recurse -Force apps/api/.wrangler/state/v3/d1
   # 3. รันโครงสร้าง Migration ล่าสุดทั้งหมด (0001–0039)
   pnpm --dir apps/api run db:migrate:local
   # 4. บันทึกข้อมูลตั้งต้นและบัญชีทดสอบจำลอง
   pnpm --dir apps/api run db:seed:local
   ```
2. **การสำรองฐานข้อมูลก่อนเริ่มการทดสอบ (Pre-UAT Backup):**
   ```powershell
   # คัดลอกไฟล์ฐานข้อมูล SQLite เก็บไว้เป็น Snaphot สำรอง
   $backupDir = "apps/api/.wrangler/backup"
   New-Item -ItemType Directory -Path $backupDir -Force
   Copy-Item "apps/api/.wrangler/state/v3/d1/miniflare-D1DatabaseObject/*.sqlite" -Destination "$backupDir/pre_uat_backup.sqlite"
   ```
3. **การฟื้นฟูข้อมูลกรณีต้องการเริ่มใหม่ (Restore Procedure):**
   ```powershell
   # ปิด Worker แล้วคัดลอกไฟล์สำรองกลับมาทับ
   Copy-Item "$backupDir/pre_uat_backup.sqlite" -Destination "apps/api/.wrangler/state/v3/d1/miniflare-D1DatabaseObject/*.sqlite" -Force
   ```
