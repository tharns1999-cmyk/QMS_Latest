# ล็อกอินด้วยบัญชี Microsoft ของบริษัท (Entra ID) — สิ่งที่ IT ต้องตั้งค่า

เขียนสำหรับ IT ผู้ดูแล Microsoft 365 / Azure ของบริษัท สถานะ: โค้ดเสร็จและทดสอบกับตัวจำลอง Microsoft แล้ว **ยังไม่เคยลองกับ Entra ID จริง** ขั้นตอนด้านล่างจึงต้องยืนยันซ้ำตอนขึ้น Azure UAT

## หลักการ
- ผู้ใช้กด "เข้าสู่ระบบด้วย Microsoft" ไปยืนยันตัวตนที่ Microsoft (รวมการยืนยันสองขั้นตอนตามนโยบายของบริษัท) แล้วกลับมาเข้าระบบ QMS
- QMS จับคู่คนด้วยอีเมลกับตารางผู้ใช้ของ QMS สิทธิ์ ระดับ และแผนกยังกำหนดใน QMS เหมือนเดิม **ระบบไม่สร้างผู้ใช้ให้อัตโนมัติ** อีเมลที่ไม่อยู่ในตารางจะเข้าไม่ได้
- ในโหมดนี้ QMS ไม่มีรหัสผ่านและการยืนยันสองขั้นตอนของตัวเองอีกต่อไป (ปิดเส้นทางเหล่านั้นทั้งหมด)

## ขั้นตอนใน Entra admin center
ทำแยกกันสำหรับ UAT และ PROD (ลงทะเบียนแอป 2 ตัว)

1. **App registrations → New registration**
   - Name: `QMS Portal UAT` (หรือ `QMS Portal`)
   - Supported account types: **Accounts in this organizational directory only (Single tenant)** ห้ามเลือกแบบหลายองค์กร
   - Redirect URI: ชนิด **Web** ค่า `https://<ที่อยู่ระบบ>/api/auth/entra/callback`
2. **Certificates & secrets → New client secret** จดวันหมดอายุไว้ (ตั้งเตือนล่วงหน้า เมื่อหมดอายุคนจะล็อกอินไม่ได้) เก็บค่า **Value** ทันที เพราะดูซ้ำไม่ได้
3. **Token configuration → Add optional claim → ID** เพิ่ม `email` และ `upn` (ระบบใช้ `preferred_username` ก่อน แล้วค่อย `upn`, `email`)
4. **API permissions:** ใช้ค่าตั้งต้น (`User.Read`, delegated) พอ ไม่ต้องเพิ่มสิทธิ์อื่น
5. แนะนำ: **Enterprise applications → QMS Portal → Properties → Assignment required = Yes** แล้วเพิ่มเฉพาะผู้ใช้ QMS เป็นชั้นป้องกันเพิ่ม

## ค่าที่ต้องส่งให้ผู้พัฒนา / ตั้งเป็น Application settings ใน App Service
| ชื่อ | ค่า |
|---|---|
| `AUTH_MODE` | `entra` |
| `ENTRA_TENANT_ID` | Directory (tenant) ID ของบริษัท (GUID) |
| `ENTRA_CLIENT_ID` | Application (client) ID ของแอปที่ลงทะเบียน (GUID) |
| `ENTRA_CLIENT_SECRET` | ค่า Value ของ client secret (เก็บเป็นความลับ ห้ามใส่ในโค้ดหรือแชต) |
| `ENTRA_REDIRECT_URI` | ตรงกับที่ลงทะเบียนทุกตัวอักษร: `https://<ที่อยู่ระบบ>/api/auth/entra/callback` |

ถ้าตั้งค่าไม่ครบ ระบบจะ **ไม่เปิดให้เข้าด้วยรหัสผ่านแทน** แต่จะไม่ยอมเริ่มทำงาน (หรือปฏิเสธทุกการเข้าสู่ระบบ) เพื่อไม่ให้เกิดช่องทางเข้าที่ไม่ได้ตั้งใจ

## ก่อนเปิดใช้งานจริง ต้องตรวจ
- **อีเมลของทุกคนในตาราง QMS ต้องตรงกับอีเมลล็อกอิน (UPN) ใน Microsoft 365** ตัวอักษรใหญ่เล็กไม่สำคัญ แต่ชื่อโดเมนและการสะกดต้องตรง ใครไม่ตรงจะเข้าไม่ได้ ให้ DCC แก้อีเมลใน QMS
- ผู้ที่ลาออกหรือย้ายงานต้องถูกปิดสถานะใน QMS (ปิดบัญชี Microsoft อย่างเดียวพอสำหรับการล็อกอิน แต่สถานะใน QMS ใช้กับการเลือกผู้ทบทวน/อนุมัติ)
- ลองด้วยบัญชีจริงอย่างน้อย 1 คนต่อระดับสิทธิ์ และ 1 บัญชีที่ **ไม่ได้อยู่ใน QMS** (ต้องเห็นข้อความ "ยังไม่ได้รับสิทธิ์ใช้งาน")
- ทดสอบให้ผ่านทั้งแบบเครื่องที่ล็อกอิน Microsoft ค้างไว้แล้ว และเครื่องใหม่

## ข้อควรรู้
- การออกจากระบบ QMS ไม่ได้ออกจากบัญชี Microsoft ในเบราว์เซอร์ (เป็นปกติของ SSO) เข้าใหม่จะให้เลือกบัญชีทุกครั้ง
- ถ้าบัญชี Microsoft ของใครถูกสร้างใหม่ด้วยอีเมลเดิม ระบบจะถือว่าเป็นคนเดิม เพราะจับคู่ด้วยอีเมล หากต้องการเข้มกว่านี้ (ผูกกับรหัสบัญชีใน Microsoft) แจ้งผู้พัฒนาได้ ตอนนี้ระบบบันทึกรหัสบัญชี (oid) ลง audit log ทุกครั้งที่ล็อกอิน
- ทดลองบนเครื่องผู้พัฒนาได้โดยไม่ต้องมี Azure: `pnpm --dir apps/api run local:stack -- --microsoft` (ใช้หน้า Microsoft จำลอง)
