# รายการตรวจ Azure UAT (ครั้งแรก)

ใช้ตามลำดับ ทำเครื่องหมายเมื่อผ่าน ข้อที่ไม่ผ่านให้จดข้อความผิดพลาดที่เห็นแล้วส่งให้ผู้พัฒนา ห้ามข้ามข้อ ทุกข้อในรายการนี้ **ยังไม่เคยถูกพิสูจน์บน Azure จริง**

## A. IT เตรียมเสร็จ (ก่อนเริ่ม)
- [ ] Azure subscription พร้อม App Service (Node 24), PostgreSQL, Storage ภูมิภาคเดียวกัน
- [ ] สร้างฐานข้อมูลด้วย `LC_COLLATE C` และ UTF8 ได้จริง (ถ้า Azure ไม่อนุญาต **หยุดและแจ้งผู้พัฒนาทันที**)
- [ ] เปิด `CITEXT` ใน `azure.extensions` แล้ว
- [ ] Managed Identity ของแอปมีสิทธิ์ Storage Blob Data Contributor
- [ ] ลงทะเบียนแอปใน Entra (ล็อกอิน) และ `QMS GitHub Deploy` (ส่งงาน) แล้ว
- [ ] ตั้ง Application settings และ Startup Command ครบตาม [azure-app-deploy.md](azure-app-deploy.md)
- [ ] ตั้ง Secret/Variable ใน GitHub environment `uat` ครบ

## B. ขึ้นแอป
- [ ] รัน migration กับฐานข้อมูลสำเร็จ (`db:migrate:pg`)
- [ ] Actions > Deploy to Azure > `uat` ผ่านทุกขั้น (ถ้าแดง ส่งข้อความในขั้นที่แดงให้ผู้พัฒนา)
- [ ] `https://<ที่อยู่>/healthz` ตอบ `{"status":"ok"}`
- [ ] Log stream เห็น `api_started` ไม่มีข้อผิดพลาด
- [ ] เปิดหน้าเว็บได้ และไม่มีข้อความ CSP/blocked ใน Console ของเบราว์เซอร์

## C. ล็อกอินและสิทธิ์ (ผู้ใช้จริง)
- [ ] ล็อกอินด้วยบัญชี Microsoft ได้ อย่างน้อย 1 คนต่อระดับสิทธิ์ (DCC, QMR, ผู้ใช้ทั่วไป)
- [ ] บัญชีที่ **ไม่อยู่ใน QMS** เห็นข้อความ "ยังไม่ได้รับสิทธิ์ใช้งาน"
- [ ] ทดสอบทั้งเครื่องที่ล็อกอิน Microsoft ค้างไว้ และเครื่องใหม่
- [ ] อีเมลของทุกคนในระบบตรงกับอีเมลล็อกอิน Microsoft 365 (DCC ตรวจและแก้ก่อน)

## D. ข้อมูลและไฟล์
- [ ] เปิดเมนูหลักทุกเมนู (DCC, VCC และอื่นๆ) ข้อมูลที่ย้ายมาครบ ตัวเลขตรงกับระบบเดิม
- [ ] เรียงรายการแล้วลำดับเหมือนระบบเดิม (ยืนยันฐานข้อมูลเป็น `C`)
- [ ] อัปโหลด PDF แล้วเปิดดู/ดาวน์โหลดได้ และมีบันทึกการเปิดดูใน audit log
- [ ] ไฟล์เข้าถึงได้ **เฉพาะผ่านแอป** (ลองเปิดลิงก์ Blob ตรงๆ ต้องเข้าไม่ได้)
- [ ] ลองทุกเมนูหลักด้วยผู้ใช้ฐานข้อมูลสิทธิ์น้อย `qms_app` (ถ้าใช้ตาม azure-database-setup.md ข้อ 4)

## E. ความทนทาน
- [ ] กด Stop แล้ว log มี `api_stopping`; Start ใหม่แล้วใช้งานต่อได้
- [ ] **ซ้อมกู้คืนฐานข้อมูลจริง 1 ครั้ง** (point-in-time restore) แล้วบันทึกผลเป็นหลักฐานสำหรับผู้ตรวจ ISO
- [ ] ตั้งเตือนวันหมดอายุของ client secret ใน Entra

## F. ก่อน Cut-over (หลังผ่านทุกข้อ)
- [ ] ย้ายข้อมูลและไฟล์รอบสุดท้ายพร้อมตรวจ checksum
- [ ] ผู้ใช้ทดสอบจริงยืนยัน
- [ ] ปิด Cloudflare และเลิกใช้สคริปต์ `vcc-migrate-safe` / `vcc-migrate-raw`
