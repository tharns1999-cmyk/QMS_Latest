# VCC — Local Test Checklist (ทดลองบนเครื่องตัวเอง)

ใช้ทดลอง VCC บน localhost ก่อนส่ง UAT ทำตามทีละข้อ ติ๊ก ✅ เมื่อผลตรงกับ "ผลที่ควรเห็น"
สัญลักษณ์: 🟢 = ทดสอบผ่านเบราว์เซอร์จริง (เว็บ + API จริง + ฐานข้อมูล local) แล้ว · 🔵 = ทดสอบผ่าน API จริงเท่านั้น **ยังไม่ได้กดผ่านหน้าเว็บ** (ช่วยกดดู)

## 0. เตรียมระบบ (ทำครั้งเดียว)

**0.1 อัปเดตฐานข้อมูล local ให้ถึง migration 0039** (ถ้ามีข้อมูลทดสอบเดิมอยู่แล้ว)
```powershell
pnpm --dir apps/api run db:migrate:raw
```
ผลที่ควรเห็น: รายการ migration สุดท้ายคือ `0039_vcc_asset_hold_started_at.sql` เป็น ✅
> อย่าใช้ `db:migrate:local` — เป็นตัวสำหรับระบบจริง จะหยุดรอ `--confirm-migration` และปฏิเสธฐานข้อมูลว่าง

**0.2 หรือเริ่มใหม่หมด** (ข้อมูลทดสอบเดิมจะหาย): หยุด `dev:api` ก่อน แล้วลบโฟลเดอร์ `apps/api/.wrangler/state/v3/d1` และ `.../r2`
```powershell
pnpm --dir apps/api run db:migrate:raw
pnpm --dir apps/api run db:seed:local
```
> รัน seed **ได้ครั้งเดียวต่อฐานข้อมูลใหม่** รันซ้ำจะ error (ผู้ใช้ซ้ำ) — ถ้าซ้ำให้ทำ 0.2 ใหม่ตั้งแต่ลบโฟลเดอร์

**0.3 เปิดระบบ 2 หน้าต่าง**
```powershell
# หน้าต่าง 1 — API (ต้องใส่ ALLOWED_ORIGIN ไม่งั้นเบราว์เซอร์โดนบล็อก)
cd apps/api; npx wrangler dev --var ALLOWED_ORIGIN:http://localhost:5173
# หน้าต่าง 2 — เว็บ (ต้องตั้ง VITE_API_URL ไม่งั้นเข้า "โหมดจำลอง")
cd apps/web; $env:VITE_API_URL="http://localhost:8787"; pnpm run dev
```
เปิด http://localhost:5173 — ถ้ามีแถบสีเหลือง "โหมดข้อมูลจำลอง (DEMO MODE)" แปลว่าตั้ง `VITE_API_URL` ไม่สำเร็จ ให้ปิดแล้วทำใหม่ (ห้ามทดสอบในโหมดนี้)

## 9. ประวัติการใช้งาน (Audit Trail)

เปิดแท็บ "ประวัติการแจ้งเตือน (Audit)" และดูประวัติ VCC ด้วย dc4 — ต้องมีรายการต่อไปนี้พร้อม **ผู้ทำ** และ **เวลา**:
สร้างเครื่องมือ · สร้าง/ส่ง/ทบทวน/อนุมัติแผน (ผู้ทบทวน = qc4 ผู้อนุมัติ = qc6 ตามจริง) · บันทึกผล · อนุมัติใบงาน · ปลดระงับ · ขอ/อนุมัติแก้ไข · รันตรวจแจ้งเตือน · รับทราบ 🟢 (ตรวจครบจากการกดจริงในเบราว์เซอร์)
ประวัติการอนุมัติแผนบอกจำนวนใบสั่งงานที่เกิดขึ้น (`work_orders_generated`) · ปุ่ม "ประวัติ" ในทะเบียนเครื่องมือแสดงรายการสร้างเครื่องมือ 🟢
