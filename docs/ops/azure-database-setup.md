# ตั้งค่าฐานข้อมูล Azure Database for PostgreSQL สำหรับ QMS Portal

เขียนสำหรับ IT สถานะ: ทดสอบกับ PostgreSQL 17 บนเครื่องผู้พัฒนาแล้ว **ยังไม่เคยลองบน Azure จริง** ข้อที่ระบุว่า "ต้องยืนยัน" ให้ตรวจตอนขึ้น Azure UAT ทำแยกกันสำหรับ UAT และ PROD (คนละเซิร์ฟเวอร์หรืออย่างน้อยคนละฐานข้อมูล)

## 1. สร้างฐานข้อมูลให้ถูกชนิด (สำคัญที่สุด)
ระบบเดิมเรียงตัวอักษรแบบเรียงตามไบต์ ถ้าฐานข้อมูลใหม่ใช้การเรียงแบบภาษา (เช่น `en_US.utf8` ซึ่งเป็นค่าตั้งต้นของหลายระบบ) รายการต่างๆ จะเรียงต่างจากที่ผู้ใช้เคยเห็น เช่น ตัวพิมพ์ใหญ่/เล็ก รหัสเอกสารที่มีขีดและตัวเลข

```sql
CREATE DATABASE qms WITH ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;
```

ระบบ **ไม่ยอมเริ่มทำงาน** ถ้าฐานข้อมูลไม่ใช่ `C` และ `UTF8` และจะแจ้งสาเหตุใน log (`database_set_up_wrong`) สร้างฐานข้อมูลผิดแล้วแก้ทีหลังไม่ได้ ต้องสร้างใหม่ (ต้องยืนยัน: Azure อนุญาตให้ระบุ LC_COLLATE เป็น C ตอนสร้างฐานข้อมูลหรือไม่ ถ้าไม่ได้ แจ้งผู้พัฒนาทันที)

## 2. เปิดส่วนเสริม CITEXT
ระบบใช้ส่วนเสริม `citext` ให้อีเมลไม่สนตัวพิมพ์เล็กใหญ่ (เหมือนเดิม)
1. ที่ Server parameters ตั้ง `azure.extensions` ให้มี `CITEXT`
2. เครื่องมือย้ายข้อมูลจะรัน `CREATE EXTENSION IF NOT EXISTS citext` เอง ผู้ใช้ที่ใช้ย้ายข้อมูลต้องเป็น admin ของเซิร์ฟเวอร์ (ต้องยืนยัน)

## 3. การเชื่อมต่อ
- ต้องใช้ SSL: ใส่ `?sslmode=require` ท้าย `DATABASE_URL`
  `postgres://<user>:<password>@<server>.postgres.database.azure.com:5432/qms?sslmode=require`
- รหัสผ่านเก็บเป็น Application setting ของ App Service ไม่ใส่ในโค้ดหรือแชต
- `DATABASE_POOL_MAX` (ค่าตั้งต้น 10) ต้องไม่เกินจำนวนการเชื่อมต่อที่ขนาดเซิร์ฟเวอร์ที่เลือกรองรับ (ต้องยืนยัน)
- การเขียนข้อมูลของระบบเข้าคิวทีละรายการ (ใช้ advisory lock) ผู้ใช้ 20-30 คนไม่มีผลต่อความเร็ว อย่าปิดกลไกนี้

## 4. ผู้ใช้ของแอป (แนะนำสำหรับ PROD) — ต้องยืนยัน
ใช้ admin ย้ายข้อมูล แล้วให้แอปเชื่อมต่อด้วยผู้ใช้ที่มีสิทธิ์น้อยกว่า:
```sql
CREATE ROLE qms_app LOGIN PASSWORD '<รหัสผ่าน>';
GRANT CONNECT ON DATABASE qms TO qms_app;
GRANT USAGE ON SCHEMA public TO qms_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO qms_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO qms_app;
```
(ตารางบันทึกการใช้งาน audit_log มีตัวกันแก้ไขและลบอยู่แล้ว ไม่ขึ้นกับสิทธิ์นี้) ทดสอบทุกเมนูหลักด้วยผู้ใช้นี้ตอน UAT ก่อนใช้จริง

## 5. สำรองและกู้คืน
- เปิดการสำรองอัตโนมัติและ point-in-time restore ตั้งอายุเก็บตามนโยบายบริษัท (PROD แนะนำเก็บนานที่สุดเท่าที่ทำได้)
- **ซ้อมกู้คืนจริงอย่างน้อย 1 ครั้งตอน UAT** แล้วบันทึกผลไว้เป็นหลักฐานสำหรับผู้ตรวจสอบ ISO

## 6. ภูมิภาคเก็บข้อมูล
เลือกภูมิภาคเดียวกันทั้งฐานข้อมูล ที่เก็บไฟล์ และแอป และยืนยันกับบริษัทว่าข้อมูลคุณภาพเก็บนอกประเทศได้หรือไม่ก่อนเลือก
